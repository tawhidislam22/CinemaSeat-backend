# Poridhi CI/CD Setup

## One-time self-hosted runner setup

1. Open the GitHub repository and go to **Settings → Actions → Runners → New self-hosted runner**.
2. Select **Linux** and **x64**.
3. On the Poridhi VM, change to the home directory and run the download and extraction commands generated by GitHub:

   ```bash
   cd ~
   # Paste GitHub's generated runner download commands here.
   ```

4. Run GitHub's generated configuration command. Its registration token is temporary and must not be committed:

   ```bash
   ./config.sh --url https://github.com/R3d1m/CinemaSeat-Back --token YOUR_GITHUB_GENERATED_TOKEN
   ```

5. Accept the default runner group, labels, and work folder. Use `poridhi-vm` as the runner name if desired.
6. Install and start the runner service from the extracted `actions-runner` directory:

   ```bash
   sudo ./svc.sh install
   sudo ./svc.sh start
   ```

7. Give the runner's operating-system user access to Docker, then restart the runner service:

   ```bash
   sudo usermod -aG docker "$USER"
   sudo ./svc.sh stop
   sudo ./svc.sh start
   ```

8. Confirm the runner is **Idle** under **Settings → Actions → Runners**.

## Workflow behavior

- `.github/workflows/ci.yml` runs on pull requests and pushes to `main` using GitHub-hosted runners.
- CI detects changed components and builds their Docker images.
- `.github/workflows/cd.yml` runs only on pushes to `main` using the self-hosted Poridhi runner.
- CD executes `docker compose up -d --build` directly on the VM.

## Branch protection

After CI has run successfully, create a branch protection rule for `main`, enable **Require status checks to pass before merging**, and select the CI `build` check.

Never commit the runner registration token. GitHub generates it only for runner registration.
